Parameters

Parameters are host-owned inputs. The host passes them in via parameterValues; the user edits them in the parameter panel and confirms with Apply. Nothing inside the viewer writes to parameters — drills / clicks go to Variables instead.

Each section below is a live report. Toggle the parameter panel via the Settings icon in the viewer toolbar, enter values, and press Apply to refresh.

1 · Simple types (text, numeric, date, date-range)

The text, numeric, date-picker, and date-range-picker parameter types combined into a multi-clause rowVisibleExpr.

Simple parameter types

All four inputs are parameters. Enter values in the panel and press Apply. The table's rowVisibleExpr combines them with IsEmpty guards so leaving a field blank disables its filter.

Apply-on-click flow

The parameter panel buffers edits locally until the user presses Apply. That one-shot commit is on purpose:

  • Single datasource refetch per user intent. Every parameter flows into every datasource plugin’s fetch(config, parameters). Applying once avoids hammering the plugin on every keystroke of a free-text filter.
  • URL hash stays stable. When syncParamsToHash is on, the hash updates only on Apply, so a shared link exactly reproduces what the user intended.
  • Validation runs before commit. Apply is disabled until every mandatory / regex / min-max rule passes — no intermediate invalid state leaks into parameterValues.
  • onParameterChange fires on Apply, not on keystroke. The host-visible state is always valid.
